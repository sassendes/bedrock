---
title: "Architecture"
description: "The layers of a bedrock tenant and why each part was picked."
layout: "architecture"
layers:
  - name: "Runtime"
    parts:
      - name: "Falco"
        does: "Watches every node for runtime events such as a shell spawned in a container or a sensitive file read."
        why: "Events go to stdout and Alloy ships them to Loki. Dropping falcosidekick left one less component to run."
      - name: "Reloader"
        does: "Restarts a component when the ConfigMap it reads changes."
        why: "Scoped to ConfigMaps only. Secrets come from OpenBao and are read again from memory without restarts."
  - name: "Observability"
    parts:
      - name: "Prometheus and Alertmanager"
        does: "Scrape every component and fire the alert rules that ship with the platform."
        why: "Two Prometheus replicas spread across nodes. Alertmanager has no login of its own so only the network policy decides who reaches it."
      - name: "Loki and Tempo and Alloy"
        does: "Logs and traces. Alloy runs on every node and ships them in."
        why: "Loki deletion is disabled so nobody inside the cluster can erase the logs."
      - name: "Grafana"
        does: "Dashboards for every layer read from Prometheus and Loki and Tempo."
        why: "One replica by choice. Dashboards and datasources are files in ConfigMaps so a restart loses nothing."
  - name: "Secrets"
    parts:
      - name: "OpenBao"
        does: "Three pods on raft hold every component's secrets. Each pod logs in as its own service account and reads only its own path."
        why: "An audit trail and rotating credentials without a paywall. External Secrets was rejected because it copies secrets into etcd."
        fails: "Running pods keep their secrets in memory and keep working. A new pod waits until OpenBao is back."
      - name: "Secrets Store CSI driver"
        does: "Mounts each pod's secrets as files in memory and refreshes them every two minutes."
        why: "Built from reviewed upstream parts in days instead of a custom security product in months."
  - name: "Data"
    parts:
      - name: "CloudNativePG"
        does: "Three PostgreSQL clusters. A primary with synchronous replication plus a live replica and a replica five minutes behind."
        why: "The delayed replica keeps a copy from before a bad DROP for five minutes. Point in time restore covers the rest."
        fails: "One instance lost and CloudNativePG promotes inside the cluster. The whole cluster lost and the failover controller promotes the live replica."
      - name: "Failover controller"
        does: "bedrock's own controller. Observers vote with signed proof and a verifier checks four witnesses before anything moves."
        why: "Timeouts promote on a guess. A network blip can look like a dead primary and two primaries means data that never merges back."
        fails: "Measured at 66 seconds with 0 bytes lost when cluster-1 was killed."
      - name: "Backups"
        does: "Write ahead logs stream to object storage and base backups run every six hours. Kept for 30 days."
        why: "Restore any second of the last 30 days into a new cluster beside the running one."
  - name: "Storage"
    parts:
      - name: "Longhorn"
        does: "Replicated block storage with every volume encrypted with LUKS."
        why: "Ceph was rejected. Longhorn already does block and shared volumes for far less to operate."
      - name: "Garage"
        does: "S3 object storage for the backups and the logs. Three pods with three copies of every object."
        why: "MinIO's community edition is unmaintained and its successor is paid. Ceph's gateway is heavy for an S3 only job."
        fails: "No single pod holds the only copy so losing one loses nothing."
  - name: "Admission"
    parts:
      - name: "Kyverno"
        does: "Admission policies written in CEL. Resource limits and the registry allowlist and the copies of each database's CA."
        why: "Policies are code in the repo and every image must be pinned by digest from an allowed registry."
      - name: "Pod Security"
        does: "Platform services run at the restricted level. Only the node agents that need the host run privileged in their own namespace."
        why: "Built into Kubernetes with nothing extra to run."
      - name: "ValidatingAdmissionPolicy"
        does: "Gates every action of the failover controller inside the API server itself."
        why: "It lives in the API server so the controller's pods can always be recreated even while Kyverno is down."
  - name: "Network"
    parts:
      - name: "Cilium"
        does: "Default deny in every namespace. Each flow is allowed by name and every plain HTTP call is checked at layer 7. Traffic between nodes is encrypted with WireGuard."
        why: "No pod can silence an alert or delete logs or reach an admin API. Nothing reaches the internet."
      - name: "Hubble"
        does: "Records every flow and every flow that a policy dropped."
        why: "Probing gets seen. A dropped flow is evidence."
  - name: "Kubernetes"
    parts:
      - name: "RKE2"
        does: "Three control plane nodes with the CIS profile and audit logging and secrets encrypted in etcd."
        why: "k3s was rejected. Audit and Pod Security and the CIS profile come built in."
      - name: "The bootstrap"
        does: "One Ansible run from empty machines to a verified tenant."
        why: "No GitOps controller in the cluster. Write access to a repo it watches would equal cluster admin."
---
